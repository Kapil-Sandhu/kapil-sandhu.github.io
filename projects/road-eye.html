1. Executive Summary & Edge Vision Motivation

RoadEye is an intelligent vision-based edge traffic monitoring and vehicle counting system. Built leveraging YOLO (You Only Look Once) deep learning object detection architecture and OpenCV, the system delivers automated multi-class vehicle detection, localized line-crossing counting, and dynamic telemetry visualization from raw video feeds.

⚡ The Edge Compute Bottleneck

Running deep convolutional object detectors across high-resolution 1080p/4K surveillance feeds on power-constrained edge hardware introduces severe thermal throttling and frame dropping. High-overhead sky, shoulder, and horizon pixels consume 70%+ of inference time needlessly.

🎯 Algorithmic ROI Extraction Solution

RoadEye isolates an active detection corridor spanning $[Y_1:Y_2, X_1:X_2]$ around the virtual counting line, passing only the cropped sub-image to YOLO while maintaining full-frame fidelity for video recording.

🔍 Multi-Class Categorization

Unlike physical inductive loops or radar sensors that only detect metallic presence, RoadEye visually identifies and filters specific classes: cars, freight trucks, buses, and motorbikes.

🖥️ Screen-Adaptive Display Engine

Dynamically queries connected display metrics via `screeninfo`, scaling GUI windows proportionally to prevent off-screen overflow while encoding original 1080p video outputs in the background.

📐

2. Mathematical Formulations & Geometric ROI Calculus

2.1 Dynamic Spatial Geometry Calibration

Rather than hardcoding static pixel coordinates, RoadEye dynamically calculates geometric zones based on the input stream's native resolution $(W, H)$:

$$Y_{\text{line}} = 0.80 \times H, \quad X_1 = 0.15 \times W, \quad X_2 = 0.80 \times W$$
$$Y_1 = \max(0, Y_{\text{line}} - 0.30H), \quad Y_2 = \min(H, Y_{\text{line}} + 0.18H)$$

2.2 Spatial Compute Reduction Ratio & FLOPs Saved

By restricting YOLO inference to the active ROI slice $[Y_1:Y_2, X_1:X_2]$, the processed tensor area ratio is:

$$\text{Area Ratio} = \frac{(Y_2 - Y_1) \times (X_2 - X_1)}{H \times W} = \frac{0.48H \times 0.65W}{H \times W} = 0.48 \times 0.65 = \mathbf{31.2\%}$$

This results in an exact 68.8% reduction in total input pixel tensor volume passed to the convolutional backbone.

2.3 Local-to-Global Coordinate Transformation Algebra

Because YOLO operates within the cropped coordinate space $\mathbb{R}^2_{\text{crop}}$, detection bounding box coordinates $(x_1, y_1, x_2, y_2)_{\text{crop}}$ are transformed back to the global frame coordinate system $\mathbb{R}^2_{\text{global}}$:

$$x_{1,\text{global}} = x_{1,\text{crop}} + X_1, \quad y_{1,\text{global}} = y_{1,\text{crop}} + Y_1$$
$$c_x = x_{1,\text{global}} + \frac{x_{2,\text{global}} - x_{1,\text{global}}}{2}, \quad c_y = y_{1,\text{global}} + \frac{y_{2,\text{global}} - y_{1,\text{global}}}{2}$$

2.4 Centroid Line-Crossing Collision Condition

Vehicle counting triggers when a detected vehicle centroid satisfies the spatial boundary condition:

$$Y_{\text{line}} - \delta < c_y < Y_{\text{line}} + \delta \quad (\delta = 5\text{ pixels}) \implies \text{Counter} \leftarrow \text{Counter} + 1$$

3. Core Implementation & Execution Pipeline

ROI Slicing & Inference Loop

Core execution pipeline illustrating the dynamic frame slicing, YOLO forward pass, coordinate remapping, and centroid collision detection: 

# 1. Dynamic Geometry Setup
line_y = int(height * 0.80)
x_start = int(width * 0.15)
x_end = int(width * 0.80)
crop_y1 = max(0, line_y - int(height * 0.30))
crop_y2 = min(height, line_y + int(height * 0.18))

# 2. Frame Slicing & YOLO Inference
cropped_frame = frame[crop_y1:crop_y2, x_start:x_end]
results = model(cropped_frame, verbose=False)
detections = results[0].boxes.data.cpu().numpy()

# 3. Global Coordinate Translation
for det in detections:
    x1, y1, x2, y2, conf, cls_id = det
    if conf > 0.20 and model.names[int(cls_id)] in TARGET_CLASSES:
        gx1, gy1 = int(x1) + x_start, int(y1) + crop_y1
        gx2, gy2 = int(x2) + x_start, int(y2) + crop_y1
        cx, cy = (gx1 + gx2) // 2, (gy1 + gy2) // 2
        
        # 4. Centroid Line-Crossing Check
        if abs(cy - line_y) < 5:
            vehicle_counter += 1
            print(f"Vehicle Passed: {vehicle_counter}")
Adaptive Screen Display & Writer
1. Hardware Display Scaling:

Queries connected monitor resolution via `screeninfo` and dynamically applies scale factor $S = \min(W_{\text{mon}}/W, H_{\text{mon}}/H, 1.0)$ so GUI windows never exceed screen boundaries.

2. High-Fidelity MP4 Archival:

While GUI preview is scaled down for smooth user viewing, `cv2.VideoWriter` encodes full-resolution $1920 \times 1080$ annotated frames with the `'mp4v'` codec at native video FPS.

3. HUD Graphic Overlays:

Draws real-time vehicle bounding boxes, class labels with confidence percentages, the red virtual counting tripwire line, and total vehicle tally statistics.

6. Technical Limitations & Future Engineering Enhancements

1. Multi-Object Tracking (ByteTrack / BoT-SORT)

Integrating `model.track(..., persist=True)` will assign persistent track IDs across frames, completely eliminating threshold jumps for high-speed vehicles.

2. Directional Vector Flow (Inbound vs. Outbound)

Implementing motion vectors $\vec{v} = (c_{x,t} - c_{x,t-1}, c_{y,t} - c_{y,t-1})$ will allow distinguishing between opposing lanes of traffic automatically.

3. Per-Class Telemetry Breakdown

Splitting the aggregated count into discrete registers for each category: $\text{Total} = N_{\text{car}} + N_{\text{truck}} + N_{\text{bus}} + N_{\text{bike}}$.

4. TensorRT & Edge Hardware Compilation

Exporting weights to TensorRT engines (`best.engine`) for sub-5ms deployment on embedded NVIDIA Jetson platforms.
